# YouTube 一站式工作流（下载 + 学习笔记）

## 概述

将 YouTube/B站 视频**一站式处理**，从原始链接到最终产出只需一条指令：

```
视频链接 → [Phase 0] 获取中文标题
         → [Phase 1] 模式判断
              ├─ 学习模式（无"下载"） → 跳过下载，直接获取字幕
              └─ 学习下载模式（有"下载"） → 下载视频
                   ├─ 检测中文配音音轨 → 有 → 合并中文音轨 ✅
                   └─ 无 → 检测是否英文视频 → 是 → AI中文配音 → ✅
                                              └─ 否 → 保留原音轨
         → [Phase 2] 获取完整字幕
         → [Phase 3~6] 撰写结构化学习文档（含过程还原、可视化）
         → [Phase 7] 统一交付：视频(可选) + HTML 学习文档 → 同一文件夹
```

**本仓库整合了视频下载与学习笔记两大模块于一体：**

---

## 何时触发

**两种模式**：

| 模式 | 触发关键词 | 行为 |
|------|-----------|------|
| **学习** | "学习这个视频"、"帮我学习"、"分析这个视频"、"学习 [链接]" | 只获取字幕 + 生成结构化学习笔记（不下载视频） |
| **学习下载** | "学习下载"、"下载并学习"、"下载并整理"、"下载这个视频" | 下载视频 + 配中文音轨/字幕 + 生成笔记 |

**自动触发条件**（符合任一即触发）：
- 用户提供 YouTube/B站 链接 + 以下任一关键词：学习、下载、翻译、笔记、整理、总结、学习笔记、学习文档、听课、做笔记、配音、字幕
- 用户说："帮我学习这个视频" + 链接
- 用户说："帮我下载这个视频"、"下载并做笔记"、"把视频翻译成中文"、"生成学习文档"
- 用户说："帮我整理这个视频" + 链接

**不触发的情况**：
- 仅提供链接，没有明确操作意图
- 仅要求提取字幕（无笔记需求）→ 仅执行 Phase 0~2

> **关键区分**：用户是否明确说了"下载"。
> - 说"学习" → 不下载视频，只获取字幕和生成笔记
> - 说"学习下载" → 下载视频 + 字幕 + 笔记

## 前置条件

### 必需工具

| 工具 | 安装方式 | 用途 |
|------|---------|------|
| **Python 3.8+** | [python.org](https://python.org) | 所有脚本运行环境 |
| **yt-dlp** | `pip install yt-dlp` | YouTube/B站 下载核心 |
| **ffmpeg** | `winget install ffmpeg` | 音视频合并/处理 |
| **youtube-transcript-api** | `pip install youtube-transcript-api` | YouTube 字幕获取（首选） |
| **requests** | `pip install requests` | 视频元数据获取 |
| **Node.js** | `winget install nodejs` | yt-dlp JS runtime |

### 可选工具

| 工具 | 安装方式 | 用途 |
|------|---------|------|
| **faster-whisper** | `pip install faster-whisper` | 语音识别（AI配音必需） |
| **edge-tts** | `pip install edge-tts` | ⭐中文语音合成（AI配音核心，推荐优先安装） |
| **pyvideotrans** | [GitHub](https://github.com/jianchang512/pyvideotrans) | 全自动视频翻译配音（更强大但安装复杂） |
| **markdown** | `pip install markdown` | Markdown→HTML 降级输出 |

> **AI 配音建议**：建议至少安装 `edge-tts`（pip install edge-tts），它是 AI 配音最轻量可靠的方案。
> 安装后，所有英文视频下载后会自动配上中文语音。

### 批量安装

```bash
pip install -r requirements.txt
pip install yt-dlp edge-tts
```

### 网络要求

- 需要能够访问 YouTube（建议配置代理）
- 默认代理地址 `http://127.0.0.1:2080`（通过环境变量 `HTTP_PROXY` 或 `config.yaml` 修改）

## Phase 1：视频处理（学习模式 vs 学习下载模式）

### 模式判断

**学习模式**（用户说"学习"但没说要"下载"）：
- 跳过视频下载，直接进入 Phase 2 获取字幕
- 获取字幕后直接进入 Phase 3~6 生成笔记
- 最终产出：HTML 学习笔记 + 字幕文件（无视频文件）

**学习下载模式**（用户说"学习下载"或明确要求"下载"）：
- 执行完整视频下载流程
- 获取字幕
- 生成笔记
- 最终产出：视频文件 + HTML 学习笔记 + 字幕文件

> **关键区分**：用户是否明确说了"下载"。
> - "学习这个视频" → 学习模式（不下载）
> - "学习下载这个视频" → 学习下载模式（下载）

---

### 学习下载模式：下载与中文处理

**优先级链**：🥇中文配音音轨(140-16) → 🥈AI中文配音（英文视频，edge-tts） → 🥉保留原始音轨

1. **下载视频**（最佳画质优先）
2. **检测中文配音音轨**（yt-dlp -F 检测 140-16 格式）
3. **如果已有中文配音音轨** → 直接合并，完成 ✅
4. **如果没有中文配音音轨**：
   - 判断是否为英文视频
   - 如果是英文视频 → **运行 AI 中文配音**（edge-tts / ai_dub_core.py）
   - 如果不是英文视频 → 保留原始音轨

> **AI 配音前提**：需要安装 `edge-tts`（`pip install edge-tts`）和 `faster-whisper`（`pip install faster-whisper`）。
> 如果未安装，则保留原始音轨并提示用户。

### 1a. 下载视频（基础命令）

```powershell
# 下载到输出目录（不自动AI配音，仅下载）
# 最终输出目录由 Phase 9 统一管理

# 先用 yt-dlp 下载最佳画质视频（临时输出到 TEMP）
$title = "..."  # 从 Phase 0 获取
$tempDir = "$env:TEMP\yt_download_${title}"
mkdir $tempDir -Force > $null

# 检测中文音轨
python -m yt_dlp --no-check-certificates --js-runtimes node -F "<URL>" 2>&1 | Select-String "140-16"

# 有中文音轨 → 下载含中文音轨版本
python -m yt_dlp --no-check-certificates --js-runtimes node `
  -f "bv[ext=mp4]+140-16/bv*+ba/best" --merge-output-format mp4 `
  -o "$tempDir\${title}.%(ext)s" "<URL>"

# 无中文音轨 + 英文视频 → 下载后 AI 配音
python -m yt_dlp --no-check-certificates --js-runtimes node `
  -f "bv*+ba/best" --merge-output-format mp4 `
  -o "$tempDir\${title}.%(ext)s" "<URL>"

# 如果下载失败（反爬），尝试 Android 客户端模式
python -m yt_dlp --extractor-args "youtube:player_client=android" `
  --no-check-certificates -f "bv*+ba/best" --merge-output-format mp4 `
  -o "$tempDir\${title}.%(ext)s" "<URL>"
```

### 1b. AI 中文配音（学习下载模式）

当检测到视频为**英文内容且无中文音轨**时，自动执行：

```powershell
# 使用 ai_dub_core.py（跨平台完整实现）
python "$SCRIPT_DIR\ai_dub_core.py" "$videoPath" --voice "zh-CN-XiaoxiaoNeural"

# 或保留原背景音混合
python "$SCRIPT_DIR\ai_dub_core.py" "$videoPath" --keep-bgm

# 如果已有翻译好的中文文本，直接指定
python "$SCRIPT_DIR\ai_dub_core.py" "$videoPath" --text "$videoPath\..\translated.txt"

# 配音后的文件命名为：{标题}_zh_dubbed.mp4
```

**ai_dub_core.py 完整流程**：
1. 提取音频（ffmpeg）
2. faster-whisper 转录英文文本
3. 保存转录文件供用户翻译
4. 用户翻译后重新运行，指定 `--text` 参数
5. Edge TTS 分段合成中文语音
6. ffmpeg 合并音频与视频

## Phase 2：获取字幕（用于学习文档）

使用 `fetch_transcript.py` 获取完整字幕，支持**多级降级**确保任何环境都能产出内容。

### 命令

```bash
# YouTube（输出到临时目录）
python "$SCRIPT_DIR\fetch_transcript.py" "<URL>" --output "$env:TEMP\yt_notes"

# Bilibili
python "$SCRIPT_DIR\fetch_transcript.py" "https://www.bilibili.com/video/BVxxxxxxxxxx"

# 指定语言
python "$SCRIPT_DIR\fetch_transcript.py" "<URL>" --lang zh-Hans

# yt-dlp 优先（当 youtube-transcript-api 失败时）
python "$SCRIPT_DIR\fetch_transcript.py" "<URL>" --ytdlp-first
```

### 多级降级策略

| 级别 | 方法 | 说明 |
|------|------|------|
| **Level 1** | `fetch_transcript.py` | 首选：youtube-transcript-api → 降级 yt-dlp |
| **Level 2** | 第三方摘要平台 | VideoHighlight / Glasp / Eightify（标注"基于第三方"） |
| **Level 3** | 网络文字回顾 | 搜索引擎找博主回顾、论坛讨论 |
| **Level 4** | 框架性笔记 | 基于标题+简介+评论，标注"无法获取完整内容" |

> **绝不因为拿不到字幕就告诉用户"做不了"。**

### 字幕输出文件

脚本自动生成以下文件到临时目录：
- `{video_id}_transcript.json` — 带时间戳的完整字幕（AI 分析用）
- `{video_id}_transcript.txt` — 纯文本（AI 阅读用）
- `{video_id}_timestamped.txt` — 带 `[分:秒]` 时间戳的文本
- `{video_id}_info.json` — 视频元数据

### 执行后反馈

获取成功后向用户报告：
- 视频标题、总时长、平台
- 视频类型判断（授课/访谈/教程/故事）
- 预估主题数
- 快速扫描到的人名/数据/案例清单

## Phase 3：判断视频类型

拿到字幕内容后，先判断视频类型，不同采用不同的结构侧重：

| 类型 | 识别特征 | 结构侧重 | 典型例子 |
|------|---------|---------|---------|
| **授课/讲座类** | 课程、讲座、分享、演讲 | 按知识点递进，强调逻辑链条和论证路径 | 大学课程、TED、技术分享 |
| **访谈/对话类** | 对话、访谈、播客、对谈 | 按话题切分，保留双方互动，突出核心嘉宾观点 | The Diary of a CEO、播客节目 |
| **教程/操作类** | 教程、教学、上手、从零开始 | 按步骤切分，强调可复现性，附代码/命令说明 | 编程教程、软件操作、手工教程 |
| **故事/案例类** | 故事、传记、案例、复盘 | 按情节推进，保留叙事节奏，结尾提炼启示 | 人物传记、商业案例分析 |

> 类型不明确时，默认按「访谈/对话类」处理。

## Phase 4：强制预扫描

通读获取的全部字幕内容，建立「内容清单」（内部流程，不输出给用户）：

- 总主题数、总子论点数
- 人名清单（全部，含身份背景）
- 书名/文章名/论文名（全部）
- 案例/故事清单（全部，标注时间范围）
- 关键数据/统计（全部）
- 关键引语（每个主题至少 3 句备选）
- 反问/讽刺/夸张/戏剧化段落（全部）
- 提到的工具/方法/实践建议（全部）

> 写完笔记后必须拿清单逐条核对，漏一项就返工。

---

## Phase 5：主题切分

按**内容逻辑**切分主题，每个主题对应一个完整的"教学单元"：

- 每个主题包含 **4-6 个子论点**，不得少于 4 个
- 如果某个主题信息量不足 4 个子论点，合并到相邻主题
- 不得为了凑数把一个主题拆成多个薄弱主题
- **访谈类**：按话题自然转换切分，不要按时间均分
- **教程类**：按操作步骤/模块切分，确保每个主题可独立复现

## Phase 6：撰写学习文档

### 核心原则

> **不是做摘要，而是做"学习替身"——覆盖全部重要信息，但用自然叙述呈现。**
>
> **写完自己读一遍：如果读起来像"机器提取的数据报告"或"百度百科词条"，就重写。**
>
> **内容少了的笔记=废笔记。宁可多写不可少写。**
>
> **过程还原不到位=转述。如果笔记只给结论不给过程，就是高级摘要。**
>
> **推导步骤丢失=废笔记。读者知道"结论是什么"，但不知道"为什么"。**

### 文档整体结构

```
┌─────────────────────────────────────┐
│  封面区（标题、嘉宾、时长、简介）     │
├─────────────────────────────────────┤
│  为什么值得看（100字价值定位）       │
├─────────────────────────────────────┤
│  目录导航                           │
├─────────────────────────────────────┤
│  整课骨架（论证路径概括）            │
├─────────────────────────────────────┤
│  全局概念导图（Mermaid）            │
├─────────────────────────────────────┤
│  主题一 ~ 主题N（核心内容）          │
│  每个主题包含：                      │
│  · 时间段标注                       │
│  · 4-6个子论点（过程还原体）         │
│    · 结论在推导过程末尾自然浮现       │
│    · 还原讲师从A→B→C→D的思考路径    │
│  · 穿插引语、表格、图表              │
│  · 主题小结/概念导图                │
├─────────────────────────────────────┤
│  核心概念速查表                      │
├─────────────────────────────────────┤
│  行动指南 / 实践建议                 │
├─────────────────────────────────────┤
│  延伸阅读与资源                      │
├─────────────────────────────────────┤
│  参考来源                            │
└─────────────────────────────────────┘
```

### 每个主题的过程还原要求

每个子论点必须还原讲师的**推导过程**，而不是只记录最终结论：

1. **起点（问题/现象/困惑）**：讲师从什么观察或问题出发？
2. **推导过程（步骤还原）**：还原讲师的每一步推理。如果讲师用了3个论证步骤到达结论，笔记必须写3个步骤，每个步骤不少于30字。
3. **关键转折/回应**：如果讲师在过程中遇到了反对意见、质疑，必须保留质疑→回应的完整来回。
4. **结论自然浮现**：结论在子论点末尾自然出现，不在开头暴露。
5. **衔接到下一段**：与下一个子论点的逻辑关联。

### 过程还原的深度分层

| 内容类型 | 策略 | 理由 |
|---------|------|------|
| **核心观点/关键转折** | 完整还原（保留犹豫→补充→修正的完整过程） | 展示思维复杂性 |
| **次要观点/辅助说明** | 保留关键转折点，压缩琐碎细节 | 保留转折，删除停顿 |
| **事实性回答** | 直接陈述结论 | 没有思想演进过程 |
| **寒暄/过渡** | 一句话带过 | 不值得展开 |

### 叙述规则

**禁止机械罗列**：
```
❌ 坏：- 讲师解释... - 讲师提到... - 讲师指出...
```

**禁止结论先行**：
```
❌ 坏写法（结论先行，过程压缩为3句话）：
1. **Greene 认为权力是内在控制感**：他说权力不是政治地位...
（结论开头顶出，后续是并列论据堆砌）
```

**必须写成过程还原**：
```
✅ 好写法（先过程后结论，还原推导步骤）：
1. **Greene 先打破一个根深蒂固的误解**：大多数人一想到权力...
   （结论在段落末尾自然浮现，读者跟着走完了推导路径。）
```

**必须遵守的规则**：
- 用编号（1. 2. 3.）组织子论点
- 每个子论点开头有**粗体引导语**，从问题/现象出发
- 引语穿插在叙述中，用 `>` 引号标出
- 用"首先""然后""接着""讲师转而指出""最后他总结道"等连接词还原时间线
- 读起来像"有人带你一步一步走过了讲者的思考过程"
- **禁止口语化逐句还原**：不要写"他说…然后他说…接着他又说…"
- 提取逻辑骨架，用因果关系连接，不是按时间顺序复述每一句话

### 引语处理（重要）

所有英文引语必须加中文翻译：

```html
<blockquote>
  <p>"English quote text here..."<br><span class="trans">"中文翻译文本..."</span></p>
  <cite>—— Peter Jiang</cite>
</blockquote>
```

### 字数要求

| 视频时长 | 笔记最低总字数 |
|---------|---------------|
| < 15 分钟 | ≥ 2,500 字 |
| 15-30 分钟 | ≥ 4,500 字 |
| 30-60 分钟 | ≥ 8,000 字 |
| 60-120 分钟 | ≥ 12,000 字 |
| > 120 分钟 | ≥ 16,000 字 |

> 字数达标后停止，不要过度展开。超20%为上限。

## Phase 9：文件输出与交付

### 统一交付结构（视频 + 学习文档 → 同一文件夹）

所有产出统一放在一个文件夹中，视频和笔记在一起，一目了然：

```
桌面/学习笔记产出/                          ← 根目录
└── {视频标题}_学习笔记/                    ← 每个视频一个独立文件夹（包含所有产出）
    ├── {视频标题}_学习笔记.html            ← 主文档（直接浏览器打开）
    ├── {视频标题}.mp4                      ← 视频文件（含中文配音，如适用）
    │    或 {视频标题}_zh_dubbed.mp4        ← AI配音版本（如适用）
    ├── {video_id}_transcript.json          ← 字幕 JSON
    ├── {video_id}_transcript.txt           ← 字幕纯文本
    ├── {video_id}_timestamped.txt          ← 带时间戳字幕
    └── {video_id}_info.json                ← 视频元数据
```

> **设计原则**：同一个视频的所有产出（视频、笔记、字幕）放在一个文件夹里。
> 用户打开一个文件夹，视频和笔记都在手边，看完视频直接看笔记，非常清晰。

### 配置参考

下载设置通过 `config.yaml` 控制，但注意视频最终会移动到统一输出文件夹中：

```yaml
# $ROOT_DIR\config.yaml

proxy: 'http://127.0.0.1:2080'
# download_dir 仅用于临时下载，最终视频会移到统一输出文件夹

format:
  best: 'bv[ext=mp4]+140-16/bv*+ba/best'     # 中文音轨优先，否则最佳画质+最佳音频
  subs: 'bv[ext=mp4]+ba[ext=m4a]'               # 字幕模式
  audio: '140-16/ba*'                            # 音频模式

ai_dub:
  engine: 'edge-tts'                      # 默认使用 edge-tts（轻量可靠）
  voice: 'zh-CN-XiaoxiaoNeural'           # Edge TTS 语音名称
  source_language: 'en'                    # 源语言（英文）
  target_language: 'zh-cn'                # 目标语言（中文）
```

### 工作目录隔离原则（强制）

- **YouTube 学习笔记工具文件夹** 最终不得出现任何新的产出文件
- 所有中间生成文件必须在交付前删除或移动至对应输出目录
- 工作目录应始终保持干净，只保留工具脚本和技能说明

### 自动清理

交付完成后，立即删除工作目录中所有中间产出：
- 主题切分文件、子代理生成的分块文件
- 所有临时脚本、临时目录（`.ytdlp_tmp_*`、`.bili_tmp_*`）
- 之前任务遗留的旧文件

## 十三条铁律（绝对禁止）

1. ❌ **遗漏**核心信息：人名、书名、案例、数据，缺一项都不行
2. ❌ **机械罗列**：连续使用"讲师+动词"句式超过 2 句
3. ❌ **总结式写作**：把 10 分钟内容压成 2 行
4. ❌ **压平语气**：把反问改陈述、把讽刺改中性
5. ❌ **空洞套话**："这个问题非常复杂"等废话
6. ❌ **附录式结构**：文末放人物索引（概念速查表除外）
7. ❌ **到处时间戳**：仅主题开头标注一次
8. ❌ **模糊表述**：写"等等""之类""一些"
9. ❌ **结论先行**：子论点开头50字内不能出现结论
10. ❌ **一步到位压缩推导**：讲师用了N步，笔记必须保留N步
11. ❌ **只记最终回应**：质疑→回应的完整来回必须保留
12. ❌ **只记嘉宾最终答案**：犹豫→补充→修正必须保留
13. ❌ **口语化逐句还原**：禁止"他说…然后他说…"翻译腔
